Pilot, dev seed 7, CPU on GitHub Actions, no training. Raw verdicts in `results/e0_run1/`. Sample sizes are small (n = 36 to 60 per criterion), so differences of a few points mean little. The 1.5B jobs are pending.

## Reading

1. **My main bet failed at its first test.** Controlling with a distractor barely reduced the offset, so the noise isn't format, as I'd argued in draft 1. It's content: an unknown answer is high-entropy, and any context pushes it around.
2. **Part of the deployed failure may be the test's own fault.** It labels every generated question positive, though many aren't answered by the episode. Whether that explains 0.57 is unknown; E0b separates them.
3. **Known vs. fictional at 0.997 is the surprise, and it deserves suspicion.** It compares real entities with invented names, so name familiarity is a confound. It needs the within-fact test (H8).
4. If H8 holds, the framework's value shifts from *deciding what to teach* to *knowing what was learned*: an oracle-free audit, which the literature search did not find. That is a hypothesis, not a result.

## Practical

- Parse rate on generated questions: 0.90 base, 1.00 Instruct. Quality is visibly poor; many are irrelevant or invented.
- Cost on CPU: 0.5B base 51 min, Instruct 71 min. Name-familiarity check: no hits, nothing replaced.
- All generation ran without fp16. GPU paths remain unexercised.
